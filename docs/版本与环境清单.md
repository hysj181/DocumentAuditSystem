## 5. PaddlePaddle 实际 CPU/GPU 状态

实际检查结果：

```text
paddle.is_compiled_with_cuda() = False
paddle.device.cuda.device_count() = 0
paddle.device.get_device() = cpu
```

结论：

- 当前机器没有可用 CUDA 设备。
- 当前 Paddle 为 CPU 版。
- `local_gpu` 只是项目一/项目三的解析模式标签，**不代表实际 GPU 推理**。
- 当前实际 Paddle 推理设备为 **CPU**。
- 未验证真实 GPU 推理。

## 9. 已知环境限制

1. PDF 使用 CPU 推理，速度较慢。
2. Paddle CUDA 当前不可用，未验证真实 GPU 推理。
3. `local_gpu` 名称与实际 CPU 设备之间容易误解。
4. `cloud_api` 需要网络、Token 和配额；本次未验证真实云端调用。
5. 模型首次下载体积较大，初始化耗时较长，加载后内存占用较高。
6. 复杂 PDF 表格、多级表头、合并单元格、无线框表格仍可能需要人工核对。
7. 隔离的部分成功任务中曾出现一次瞬态 `WinError 5` 交付目录重命名失败，`resume` 后恢复，重跑未复现。
8. 项目三为单机文件锁，不是跨机器分布式锁。
9. 项目一、项目二未配置 Ruff；项目三 Ruff 已通过。
10. 根目录当前没有统一 Git 仓库；项目二、项目三虽有独立 `.git`，但均无初始提交，项目一没有 `.git`。
