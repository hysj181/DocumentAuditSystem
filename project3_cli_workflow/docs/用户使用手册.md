# 用户使用手册

## 1. 环境准备

要求：

- Windows 10/11
- Python 3.12
- uv 0.13.6
- 项目一、项目二各自 `.venv` 已存在

检查：

```powershell
cd D:\DocumentAuditSystem\project3_cli_workflow
uv run project3 --help
uv run project3 run --help
uv run project3 resume --help
uv run project3 deliver --help
```

## 2. 输入文件要求

支持：

- `.docx`
- `.pdf`

不支持：

- `.doc`
- 其他扩展名

可以输入：

- 单个文件
- 多个文件
- 文件夹
- 文件夹 + `--recursive`

说明：

- 扩展名大小写不敏感。
- 重复文件会被过滤。
- 不支持的文件会写入 `filtered_inputs`。
- 文件夹为空或没有 `.docx/.pdf` 时返回用户输入错误。

## 3. 正常运行

```powershell
uv run project3 run "<输入文件>" --output-root "<输出根目录>"
```

多文件：

```powershell
uv run project3 run "报告1.docx" "报告2.pdf" --output-root "D:\AuditOutput"
```

文件夹：

```powershell
uv run project3 run "D:\资料" --output-root "D:\AuditOutput"
```

递归：

```powershell
uv run project3 run "D:\资料" --recursive --output-root "D:\AuditOutput"
```

PDF 模式：

```powershell
# 默认本地模式
uv run project3 run "报告.pdf" --output-root "D:\AuditOutput"

# 云端模式必须显式指定，并配置 PADDLEOCR_ACCESS_TOKEN
uv run project3 run "报告.pdf" --mode cloud_api --output-root "D:\AuditOutput"
```

## 4. 常用参数

```text
--output-root, -o
--recursive
--mode local_gpu|cloud_api
--extraction-timeout
--audit-timeout
--project1-root
--project1-python
--project2-root
--project2-python
```

默认：

```text
mode = local_gpu
extraction-timeout = 1800 秒
audit-timeout = 1800 秒
```

## 5. resume 恢复命令

```powershell
uv run project3 resume <job_id> --output-root "<输出根目录>"
```

行为：

- 校验输入和任务指纹。
- 复用仍然有效的提取/审核/交付结果。
- 从第一个无效阶段继续。
- 输入或配置变化时拒绝恢复旧任务。

## 6. deliver 交付命令

```powershell
uv run project3 deliver --manifest "<任务目录>\manifest.json"
```

行为：

- 只重新整理交付目录。
- 不重新提取。
- 不重新审核。
- 适用于交付文件损坏或缺失。

## 7. 输出目录

```text
<输出根目录>/<job_id>/
├── manifest.json
├── 00_inputs/input_manifest.json
├── 01_extraction/
├── 02_audit/
├── 03_delivery/
│   ├── 审核报告.json
│   ├── 审核报告.md
│   ├── 批注文件/
│   ├── 运行摘要.md
│   └── 交付清单.json
└── 04_logs/
```

说明：

- `01_extraction` 保留项目一真实输出。
- `02_audit` 保留项目二真实输出。
- `03_delivery` 是用户最终查看目录。
- `04_logs` 保存两个子项目 stdout/stderr。

## 8. 如何阅读结果

`manifest.json`：

- `overall_status`：任务整体状态。
- `extraction_status`：提取状态。
- `audit_status`：审核状态。
- `delivery_status`：交付状态。
- `extraction_reused`、`audit_reused`、`delivery_reused`：阶段复用标记。
- `stage_history`：阶段执行历史。

`审核报告.json/.md`：

- `issue_count`：项目二发现的问题数。
- `unverified_count`：没有可验证计算表达式的记录数，不是错误。
- `annotation_manual_review_count`：批注阶段人工核实数。
- `complete_success`：项目二流程是否完整，不代表数据合规。

## 9. 常见错误处理

### 退出码 2：用户输入错误

可能原因：

- 文件不存在。
- 扩展名不支持。
- 文件夹为空。
- 项目路径或 Python 解释器配置错误。

处理：

- 检查路径和扩展名。
- 检查项目一、项目二 `.venv`。

### 退出码 3：部分完成

可能原因：

- 项目一 PDF 提取失败。
- 审核存在人工核实项。
- 交付项缺失。

处理：

- 查看 `manifest.json` 和 `03_delivery/运行摘要.md`。
- 查看失败文档和交付缺失项。

### 退出码 4：外部阶段失败

可能原因：

- 项目一未生成 batch.json。
- 项目二未生成审核报告。
- 审核报告格式错误。

处理：

- 查看 `04_logs/project1_extract.stderr.log`。
- 查看 `04_logs/project2_audit.stderr.log`。
- 使用 `resume` 重试必要阶段。

### 退出码 5：内部错误或锁冲突

可能原因：

- manifest 损坏。
- 任务被其他进程锁定。
- 交付目录写入失败。

处理：

- 检查 manifest 是否有效。
- 检查 `<任务目录>/.task.lock`。
- 确认没有其他进程正在运行同一任务。

### PDF 本地推理

当前环境为 PaddlePaddle CPU 版，`local_gpu` 只是模式标签，实际 Paddle 设备为 `cpu`。
项目一 PP-StructureV3 初始化已设置 `enable_mkldnn=False`，用于规避原
`ConvertPirAttribute2RuntimeAttribute not support` 错误；该配置已通过混合 Word + PDF
真实验收和项目一完整回归测试。关闭 MKLDNN 后 CPU 推理速度较慢。

如果 PDF 仍然解析失败，项目三会记录 `extraction_partial` 或 `extraction_failed`，
并保留项目一 stderr 日志，不会伪造成功。可查看 `04_logs/project1_extract.stderr.log`。

## 10. 安全注意事项

- 不要直接修改 `01_extraction`、`02_audit` 中的原始报告。
- 不要删除 `manifest.json`。
- 不要把 `PADDLEOCR_ACCESS_TOKEN` 写入项目文件。
- 云端模式会上传 PDF，使用前确认合规要求。
- 原始 Word/PDF 不需要复制到输出目录。
